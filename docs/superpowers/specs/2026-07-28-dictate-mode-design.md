# Режим диктовки и уведомления

**Дата:** 2026-07-28
**Статус:** утверждён

## Цель

1. Режим диктовки: хоткей → запись голоса, хоткей → стоп, транскрибированный
   текст вставляется в активное окно.
2. Видимая индикация идущей записи (уведомления; tray — позже, вне скоупа).

## Окружение

Hyprland (Wayland), Fedora. Доступны `wl-copy`, `wtype`, `notify-send`.
Хоткеи вешает пользователь в `hyprland.conf` на команды throisma.

## Команда `throisma dictate`

Тогл-семантика (аналог существующего `toggle`, но независимая):

- **Идёт диктовка** (жив pid из `throisma-dictate.pid`) → послать SIGTERM, выйти.
- **Не идёт** → начать:
  1. Уведомление «🎤 Диктовка…».
  2. Запись **только микрофона** (без системного звука) во временный WAV
     в `$XDG_RUNTIME_DIR` (fallback — temp dir).
  3. По SIGTERM/Ctrl+C — финализировать WAV, уведомление «Транскрибирую…».
  4. Транскрибировать (whisper-rs, как `transcribe`).
  5. Текст → в клипборд (`wl-copy`) **и** напечатать в активное окно (`wtype`).
  6. Уведомление с превью текста. Временный WAV удалить.

Pid-файл диктовки отдельный от pid-файла записи встреч: хоткеи не
останавливают чужой тип записи.

Флаги: `--lang` (default `auto`), `--model` / `THROISMA_MODEL` — как у
`transcribe`.

## Ошибки

Любая ошибка после остановки записи (нет модели, wtype упал и т.п.):

- уведомление с текстом ошибки;
- если транскрипция успела пройти — текст всё равно в клипборде;
- временный WAV **не** удаляется, уведомление подсказывает
  `throisma transcribe <файл>` для повтора.

## Уведомления для записи встреч

`record` / `toggle`: «⏺ Идёт запись встречи» при старте, «Готово: <файл>»
при остановке.

## Отключение уведомлений

Флаг `--no-notify` у `record`, `toggle`, `dictate` + переменная окружения
`THROISMA_NO_NOTIFY=1` (чтобы выключать без правки биндингов).
Если `notify-send` отсутствует — молча пропускать.

## Изменения в коде

- `record.rs` — `record()` параметризуется источниками (микрофон /
  микрофон+система) и путём вывода; `record`/`toggle` сохраняют текущее
  поведение.
- `transcribe.rs` — выделить `transcribe_wav(wav, model, lang) -> Result<String>`;
  команда `transcribe` пишет `.txt` как раньше, `dictate` берёт строку.
- Новый `notify.rs` — обёртка над `notify-send` через `Command`, без новых
  крейтов.
- Новый `insert.rs` — вставка текста: `wl-copy` (stdin) + `wtype` (stdin, `wtype -`).
- `main.rs` — сабкоманда `Dictate`, флаги `--no-notify`.

Новых зависимостей нет.

## Вне скоупа

- Tray-иконка (SNI/ksni), waybar-модуль.
- Стриминговая транскрипция на лету.
- Замечание: для русской диктовки модель `ggml-base` слабовата — стоит
  попробовать `ggml-small`/`ggml-medium` через `THROISMA_MODEL`.

## Тестирование

Логика почти целиком I/O (PipeWire, D-Bus, Wayland) — проверка ручная,
end-to-end: dictate старт/стоп, вставка в терминал и браузер, ошибка при
отсутствующей модели, `--no-notify`.
