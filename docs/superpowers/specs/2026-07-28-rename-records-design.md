# Названия записей (records.json)

**Дата:** 2026-07-28
**Статус:** утверждён

## Цель

Давать записям человекочитаемые названия, не переименовывая файлы.

## Хранение

`~/.local/share/throisma/recordings/records.json` — реестр метаинформации.
Ключ — стем файла (имя без расширения), он связывает WAV и `.txt` и
остаётся стабильным. Значение — объект, расширяемый под будущие
теги/описания:

```json
{
  "2026-07-28_15-33-58": { "name": "standup с командой" }
}
```

Файлы записей не переименовываются вообще: пути стабильны, санитизация и
лимиты длины не нужны (название — любой непустой текст).

## Команда

`throisma rename <название> [файл]` — по умолчанию последняя запись.
Повторный вызов заменяет название. Название задаётся только файлам из
каталога записей (пути канонизируются перед сравнением).

Запись реестра атомарная: временный файл + `rename`. При записи
вычищаются ключи, у которых больше нет WAV-файла. Отсутствующий
records.json — пустой реестр; битый — предупреждение в stderr и пустой
реестр (перезапишется при следующем rename).

## Отображение

`list` показывает название между размером и меткой транскрипта:

```
2026-07-28_15-33-58.wav     12.3 MB  standup с командой  [есть транскрипт]
```

## Изменения в коде

- Новый `src/meta.rs`: `load() -> HashMap<String, RecordMeta>`,
  `set_name(stem, name)`, команда `rename(name, file)`.
- `main.rs` — сабкоманда `Rename`.
- `list` — подтягивает названия из реестра.
- Новые зависимости: `serde` (derive) + `serde_json` — осознанное
  отступление от «без новых зависимостей», формат выбран явно.

## Вне скоупа

- Теги, описания, поиск по названию (структура реестра к ним готова).
- Команда удаления названия.
